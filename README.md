## 🌟 نظرة عامة على المشروع

يهدف **Alex Project** إلى حوسبة وتأمين دورة المبيعات بالتقسيط لشبكة فروع متعددة:
* تسجيل بيانات العملاء وأرقام هواتفهم وعناوينهم مع نظام بحث ذكي يعالج مشاكل الكتابة اليدوية للأسماء العربية.
* تحرير عقود وفواتير التقسيط وإدخال بيانات الضامنين مع الحساب الآلي للمبالغ الإجمالية والأقساط المستحقة.
* تسجيل الدفعات الشهرية، والتحديث التلقائي لحالة الفاتورة عند اكتمال السداد.
* استخراج فوري للمتأخرات المالية عبر قاعدة البيانات السحابية، مع شاشة متابعة لمسؤولي التحصيل وجدولة الاتصالات الهاتفية القادمة.
* عزل بيانات الفروع (Multi-Tenant Branch Isolation) لمنع تداخل صلاحيات موظفي الفروع، مع منح الإدارة العامة والمحاسبين رؤية شمولية لكافة الفروع.

## 🛠️ التقنيات المستخدمة (Tech Stack)

* **البيئة ومحرك التشغيل:** [Node.js](https://nodejs.org/) (v20+) مع Express.js (v5.x).
* **قاعدة البيانات:** [Neon Serverless Postgres](https://neon.tech/) متصلة أونلاين عبر مجمع اتصالات ذكي (`pg.Pool`) مع تشفير SSL.
* **إدارة وتوثيق الجلسات:** JSON Web Tokens (`jsonwebtoken`) مدمجة بربط عتادي للجهاز (`x-device-id`).
* **التشفير وحماية كلمات المرور:** `bcrypt` (10 Salt Rounds).
* **الأمان والحماية السيبرانية:** `helmet` لتأمين HTTP Headers، و `cors` للتحكم بنطاقات الوصول، و `express-rate-limit` للحماية من هجمات التخمين والإغراق (Brute-Force & DDoS).
* **التحقق من البيانات (Perimeter Validation):** مكتبة `zod` مع طبقة ميدلوير وسيطة تفحص وتطهر كافة المدخلات وتوحد الأرقام المشرقية.
* **التوثيق التفاعلي:** `swagger-ui-express` مع مواصفات OpenAPI 3.0 باللغة العربية.
* **معالجة الملفات والبيانات:** `exceljs` لمعالجة وترحيل ملايين السجلات من شيتات Excel القديمة.

## 🎯 الوظائف والمحاور المكتملة حتى الآن

### أ. الأمان والتحكم في الوصول وعزل الفروع (Auth & Security)
* **ربط عتادي بالأجهزة (Hardware Device Binding):**
  * إلزام كل طلب بإرسال الترويسة `x-device-id`.
  * ربط الحساب بجهاز الموظف المسجل، ورفض الدخول من أي جهاز آخر (`401 Device Mismatch`).
* **إغلاق التسجيل المفتوح (Registration Lockdown):**
  * منع تسجيل أي حساب جديد للمجهولين؛ إنشاء الموظفين والمحاسبين محصور بمدير النظام (`admin`).
* **عزل بيانات الفروع (Multi-Tenant Branch Scoping):**
  * موظف الفرع (`branch_employee`) مقيد تلقائياً بفرعه عند إضافة العملاء أو الفواتير.
  * منع الوصول أو تسجيل دفعات أو ملاحظات على فواتير تخص فروعاً أخرى مع إرجاع كود صريح `403 Forbidden`.
  * للمديرين (`admin`) والمحاسبين العامين (`accountant`) صلاحية الاطلاع على كل الفروع وتحديد فرع العملية اختيارياً.
* **مكافحة الهجمات:**
  * Rate Limiting مشدد على مسارات الحسابات (`/api/auth/*`) بحد أقصى 30 محاولة لكل 15 دقيقة، ومحدد عام بـ 300 طلب لكل 15 دقيقة لكامل الـ API.

---

### ب. إدارة العملاء والبحث الذكي (Customer Management)
* **إضافة عميل مع توليد الكود التسلسلي في Transaction موحدة (`POST /api/customers`):**
  * قفل تسلسلي ذري على عداد الفرع:  
    `UPDATE branches SET last_number = last_number + 1 WHERE id = $1 RETURNING code_prefix, last_number`
  * توليد `customer_code` فريد يدمج بادئة الفرع مع الرقم التسلسلي المحدث.
  * حفظ العميل، أرقام هواتفه المتعددة، وتحديد الرقم الأساسي `is_primary`.
  * حفظ العنوان الحالي للعميل في جدول `customer_addresses` مع تفعيل مؤشر `is_current = TRUE`.
* **محرك البحث الذكي والتطبيع العربي (`GET /api/customers`):**
  * خوارزمية تطبيع عربي (`normalizeArabic`) تدمج الأشكال المختلفة للحروف:
    * إزالة التشكيل والهمزات (أ، إ، آ، ء $\rightarrow$ ا).
    * توحيد التاء المربوطة والهاء (ة $\rightarrow$ ه).
    * توحيد الياء والألف المقصورة (ى $\rightarrow$ ي).
    * تحويل الأرقام المشرقية (`٠-٩`) إلى أرقام لاتينية (`0-9`).
  * البحث عبر معيار `q` يبحث بالتوازي في:
    1. الاسم المطبع (`normalized_name ILIKE %q%`).
    2. كود العميل الفريد (`customer_code ILIKE %q%`).
    3. أرقام الهواتف المرتبطة بالعميل عبر استعلام `EXISTS` فائق السرعة.
  * دعم التصفح المقسم لصفحات (`page`, `limit`).

---

### ج. إدارة الفواتير والبيع بالتقسيط (Sales & Installments)
* **إنشاء فاتورة تقسيط في Transaction ذرية (`POST /api/sales`):**
  * التحقق من سلامة العميل والفرع وصحة البيانات المالية والتواريخ.
  * احتساب إجمالي الفاتورة تلقائياً:  
    `total_amount = down_payment + (monthly_installment * installments_count)`.
  * إضافة بيانات الضامن في جدول `guarantors` وربط أرقام هواتفه.
* **تسجيل دفعة / قسط وتحديث حالة الفاتورة (`POST /api/sales/:id/payments`):**
  * تسجيل القسط وربطه بشهر الاستحقاق (`payment_month`) محتسباً لأول يوم في الشهر (`firstOfMonth`).
  * الحساب الفوري لإجمالي المدفوعات مقارنة بإجمالي الأقساط المستحقة بعد الخصم.
  * تحويل حالة الفاتورة تلقائياً إلى مكتملة السداد (`status = 'completed'`) عند دفع كامل الأقساط.
  * حماية صارمة لمنع موظف فرع من تسجيل دفعة على فاتورة لفرع آخر (`403 Forbidden`).

---

### د. إدارة المتأخرات والتحصيل (Overdue & Collection)
* **إنشاء الـ SQL View الذكية (`sale_balances`):**
  * واجهة استعلامية حسابية مباشرة على قاعدة بيانات Neon تحسب لحظياً:
    * الأقساط التي حل أجل استحقاقها حتى تاريخ اليوم استناداً إلى `first_installment_date` و `due_day`.
    * إجمالي الأقساط المسددة فعلياً لكل فاتورة نشطة (`active`).
    * صافي قيمة الأقساط المتأخرة بدقة:  
      $$\text{المتأخر} = (\text{الأقساط المستحقة} \times \text{قيمة القسط}) - \text{إجمالي المسدد}$$
* **كشف المتأخرات الفوري لمسؤولي التحصيل (`GET /api/sales/overdue`):**
  * فلترة الاستعلام حسب يوم الاستحقاق (`due_day`) وفرع الموظف (`branch_id`).
  * جلب اسم العميل ورقم هاتفه الأساسي وأحدث ملاحظة متابعة مدونة عنه.
* **تدوين نتائج الاتصال والمتابعة الهاتفية (`POST /api/sales/:id/notes`):**
  * تسجيل محتوى المكالمة (`content`)، ونوع الملاحظة (`call`, `visit`, `promise`).
  * تحديد موعد الاتصال أو المتابعة القادم (`follow_up_date`) لجدولة زيارات ومكالمات التحصيل.

### هـ. ترحيل واستيراد البيانات التاريخية (Excel Migration)
* توفير سكربتات ترحيل ذكية ومختبرة (`import-excel.ts` و `import-helpers.ts`) لاستيراد العقود القديمة من ملفات الإكسيل الضخمة (`mazen new 2026` و `الاصلاح.xlsm`).
* معالجة فروق الأعمدة، وتطبيع الهواتف، واستخراج تواريخ التسليم والاستحقاق، مع مراعاة التزامن (`concurrency: 10`) لعدم إرهاق قاعدة البيانات.

## 🛡️ قواعد الأمان والتحقق الصارم (Security & Validation Gates)

1. **انعدام ثغرات الحقن (Zero SQL Injection):**
   * الاعتماد بنسبة 100% على الاستعلامات المجهزة المعتمدة على المعلمات (Parameterized Queries: `$1, $2, ...`).
2. **صمام التحقق المحيطي (Perimeter Validation):**
   * التحقق من أرقام الهواتف المصرية (11 رقماً تبدأ بـ `010`, `011`, `012`, `015`) والأرقام الأرضية مع كود المحافظة.
   * منع القيم السالبة والصفرية في الأقساط والمبالغ المدفوعة.
   * فرض صيغة التاريخ الصارمة `YYYY-MM-DD` والتحقق من صحتها في التقويم.
3. **معالجة الأخطاء المركزية (Global Error Handling):**
   * حجب رسائل أخطاء قاعدة البيانات الداخلية أو الـ Stack Traces عن العميل لمنع تسريب بنية النظام، وإرجاع ردود منظمة بصيغة JSON.

## 💻 دليل التثبيت والتشغيل المحلي (Setup & Run Guide)

### 1. المتطلبات الأساسية
* بيئة تشغيل **Node.js** (إصدار 20 فما فوق).
* حساب وقاعدة بيانات على **Neon Serverless Postgres**.

### 2. تثبيت الحزم
```bash
npm install
```

### 3. إعداد متغيرات البيئة (`.env`)
قم بإنشاء ملف `.env` في المجلد الرئيسي للمشروع وضع فيه القيم التالية:
```env
PORT=3000
DATABASE_URL="postgresql://<user>:<password>@<neon-host>/alex_db?sslmode=require"
JWT_SECRET="your-ultra-secure-random-secret-key-at-least-32-chars-long"
ALLOWED_ORIGINS="http://localhost:3000,http://localhost:5173"
NODE_ENV=development
```

### 4. تطبيق التحديثات على قاعدة البيانات (Run Migrations)
```bash
npm run db:migrate
```

### 5. إنشاء حساب المدير الأساسي (Create First Admin)
```bash
node scripts/create-admin.js
```

### 6. تشغيل السيرفر
* **وضع التطوير (Development مع إعادة التشغيل التلقائي):**
  ```bash
  npm run start:dev
  ```
* **وضع الإنتاج (Production):**
  ```bash
  npm start
  ```

بمجرد تشغيل السيرفر، يتوفر توثيق حي وتفاعلي يتيح تجربة كافة المسارات مباشرة:

* **رابط التوثيق:** `http://localhost:3000/api-docs`
* **كيفية التجربة عبر Swagger:**
  1. اضغط على زر **Authorize** بالأعلى وضع الـ `Bearer <token>` الخاص بك، وضع قيمة الترويسة `x-device-id`.
